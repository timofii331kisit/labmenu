# labmenu

**Мови:** [Русский](README.md) | [English](README.en.md) | Українська

Консольна утиліта для Windows, написана мовою C, що об'єднує лабораторні роботи №2–8 (варіант 10) в одну програму. Кожна лабораторна працює із системою через WinAPI: файли й теки, пам'ять, диски, процеси та блокування файлів.

Запускається без аргументів (інтерактивне меню) або з аргументами (одна лабораторна, зручно для скриптів). Код повернення програми дорівнює коду повернення обраної лабораторної.

## Можливості

| Команда | Що робить |
|---------|-----------|
| `lab2` | Сумарний розмір файлів у теці (підтеки не обходяться) |
| `lab3` | Завантаження оперативної пам'яті (`GlobalMemoryStatusEx`): усього / вільно / зайнято, відсоток завантаження, порада, порівняння із заданим мінімумом |
| `lab4` | Вільні літери дисків, перебір від `Z:` до `A:` |
| `lab5` | N найбільших файлів теки, середній і медіанний розмір |
| `lab6` | Файли за класами розміру (< 1 КБ, < 10 КБ, < 100 КБ, < 1 МБ, < 10 МБ, ≥ 10 МБ): кількість, частка, сумарний і середній розмір |
| `lab7` | Знімок процесів: запис у `processes.csv`, читання назад, сортування за кількістю потоків, звіт на екран і у файл `top.txt` |
| `lab8` | Лічильник запусків у `counter.bin` під блокуванням `LockFileEx`: дві одночасно запущені копії не втрачають жодного запуску |

## Вимоги

- Windows 7 або новіша (WinAPI, `GetTickCount64`, `LockFileEx`).
- Для збирання: Visual Studio (проєкт `labmenu.slnx` / `labmenu.vcxproj`) або MinGW-w64.
- Вихідні файли в кодуванні UTF-8. Повідомлення меню українською мовою.

## Збирання

**Visual Studio.** Відкрийте `labmenu.slnx`, оберіть конфігурацію (Debug/Release, x64/x86) і зберіть проєкт. Проєкт налаштований на тулсет `v145`; якщо його не встановлено, змініть на доступний (наприклад, `v143`) у властивостях проєкту. Стандарт мови: C17.

**MinGW-w64** (наприклад, крос-компіляція з Linux):

```bash
x86_64-w64-mingw32-gcc -std=c17 -O2 -static \
    main.c lab2.c lab3.c lab4.c lab5.c lab6.c lab7.c lab8.c \
    -o labmenu.exe -lpsapi
```

## Використання

### Режим меню

Запустіть `labmenu.exe` без аргументів, оберіть пункт 1–7 (0 — вихід) і введіть параметри. Порожнє введення означає значення за замовчуванням.

```
===== labmenu =====
1. ЛР2: сумарний розмір файлів у теці
2. ЛР3: завантаження пам'яті
...
0. Вихід
```

> У меню параметри розбиваються за пробілами, тому шлях із пробілами не вийде ввести цілком. Для таких шляхів використовуйте режим командного рядка з лапками.

### Режим командного рядка

```
labmenu.exe <labN> [параметри]
```

| Команда | Параметри | За замовчуванням | Приклад |
|---------|-----------|------------------|---------|
| `lab2` | шлях до теки | обов'язковий | `labmenu.exe lab2 "C:\Users\me\Documents"` |
| `lab3` | мінімум вільної пам'яті, МБ (0–1048576) | 1024 | `labmenu.exe lab3 2048` |
| `lab4` | скільки вільних літер знайти (1–26) | 3 | `labmenu.exe lab4 5` |
| `lab5` | N (1–256) і тека | 5 і поточна | `labmenu.exe lab5 10 "C:\Windows"` |
| `lab6` | маска файлів (1–100 символів) | `*` | `labmenu.exe lab6 "C:\Windows\*.exe"` |
| `lab7` | скільки процесів показати (1–50) | 10 | `labmenu.exe lab7 20` |
| `lab8` | затримка між читанням і записом, мс (0–10000) | 3000 | `labmenu.exe lab8 5000` |

## Коди повернення

Спільні для всіх лабораторних: `0` — норма, `2` — неправильний аргумент, `3` — помилка файлу або WinAPI. Код `1` у кожної лабораторної свій:

| Команда | Значення коду `1` |
|---------|-------------------|
| `lab2` | у теці немає жодного файлу |
| `lab3` | вільної пам'яті менше за заданий мінімум |
| `lab4` | знайдено менше літер, ніж потрібно |
| `lab5` | файлів менше, ніж N (або файлів немає) |
| `lab6` | файлів, що підходять, немає |
| `lab7` | є процес із понад 100 потоками |
| `lab8` | блокування довелося чекати понад 100 мс |

Для `lab4` код `3` означає, що `GetLogicalDrives` повернула 0. У режимі командного рядка код можна перевірити так: `echo %ERRORLEVEL%`.

## Файли, що створюються

Лабораторні пишуть файли в **поточну теку**:

- `processes.csv` і `top.txt` — `lab7`;
- `counter.bin` — `lab8` (4 байти, значення лічильника).

## Перевірка lab8 (блокування файлу)

Відкрийте два вікна консолі в одній теці й запустіть майже одночасно:

```
labmenu.exe lab8 5000
```

Перша копія прочитає `0`, зачекає й запише `1`. Друга чекатиме зняття блокування, прочитає `1` і запише `2`. Без блокування обидві записали б `1`, і один запуск було б втрачено.

## Структура проєкту

```
labmenu/
├── main.c            меню та розбір командного рядка
├── labs.h            оголошення lab2_run … lab8_run
├── lab2.c … lab8.c   лабораторні роботи
├── labmenu.vcxproj   проєкт Visual Studio
└── labmenu.slnx      рішення Visual Studio
```

Кожна лабораторна — функція `labN_run(int argc, char *argv[])` із сигнатурою `main`: `argv[0]` — ім'я лабораторної, далі — параметри.

## Відомі обмеження

- `lab2` не обходить підтеки (спрощення зроблено свідомо).
- `lab5` враховує не більше 256 файлів теки; зайві пропускаються з попередженням. Якщо на межі топ-N кілька файлів однакового розміру, рядків у списку буде більше за N.
- `lab7` обробляє не більше 512 процесів.
- Шляхи довші за `MAX_PATH` (260 символів) не підтримуються.
