# labmenu

**Языки:** Русский | [English](README.en.md) | [Українська](README.uk.md)

Консольная утилита для Windows на языке C, объединяющая лабораторные работы №2–8 (вариант 10) в одну программу. Каждая лабораторная работает с системой через WinAPI: файлы и папки, память, диски, процессы, блокировка файлов.

Запускается без аргументов (интерактивное меню) или с аргументами (одна лабораторная, удобно для скриптов). Код возврата программы равен коду возврата выбранной лабораторной.

## Возможности

| Команда | Что делает |
|---------|------------|
| `lab2` | Суммарный размер файлов в папке (подпапки не обходятся) |
| `lab3` | Загрузка оперативной памяти (`GlobalMemoryStatusEx`): всего / свободно / занято, процент загрузки, совет, сравнение с заданным минимумом |
| `lab4` | Свободные буквы дисков, перебор от `Z:` к `A:` |
| `lab5` | N самых больших файлов папки, средний и медианный размер |
| `lab6` | Файлы по классам размера (< 1 КБ, < 10 КБ, < 100 КБ, < 1 МБ, < 10 МБ, ≥ 10 МБ): количество, доля, суммарный и средний размер |
| `lab7` | Снимок процессов: запись в `processes.csv`, чтение, сортировка по числу потоков, отчёт на экран и в `top.txt` |
| `lab8` | Счётчик запусков в `counter.bin` под блокировкой `LockFileEx`: две одновременно запущенные копии не теряют ни одного запуска |

## Требования

- Windows 7 или новее (WinAPI, `GetTickCount64`, `LockFileEx`).
- Для сборки: Visual Studio (проект `labmenu.slnx` / `labmenu.vcxproj`) или MinGW-w64.
- Исходные файлы в кодировке UTF-8. Сообщения меню на украинском языке.

## Сборка

**Visual Studio.** Откройте `labmenu.slnx`, выберите конфигурацию (Debug/Release, x64/x86) и нажмите «Собрать». Проект настроен на тулсет `v145`; если он не установлен, смените его на доступный (например, `v143`) в свойствах проекта. Стандарт языка: C17.

**MinGW-w64** (например, кросс-компиляция из Linux):

```bash
x86_64-w64-mingw32-gcc -std=c17 -O2 -static \
    main.c lab2.c lab3.c lab4.c lab5.c lab6.c lab7.c lab8.c \
    -o labmenu.exe -lpsapi
```

## Использование

### Режим меню

Запустите `labmenu.exe` без аргументов, выберите пункт 1–7 (0 — выход) и введите параметры. Пустой ввод означает значение по умолчанию.

```
===== labmenu =====
1. ЛР2: сумарний розмір файлів у теці
2. ЛР3: завантаження пам'яті
...
0. Вихід
```

> В меню параметры разбиваются по пробелам. Путь с пробелами в этом режиме не получится ввести целиком, для таких путей используйте режим командной строки с кавычками.

### Режим командной строки

```
labmenu.exe <labN> [параметры]
```

| Команда | Параметры | По умолчанию | Пример |
|---------|-----------|--------------|--------|
| `lab2` | путь к папке | обязателен | `labmenu.exe lab2 "C:\Users\me\Documents"` |
| `lab3` | минимум свободной памяти, МБ (0–1048576) | 1024 | `labmenu.exe lab3 2048` |
| `lab4` | сколько свободных букв найти (1–26) | 3 | `labmenu.exe lab4 5` |
| `lab5` | N (1–256) и папка | 5 и текущая | `labmenu.exe lab5 10 "C:\Windows"` |
| `lab6` | маска файлов (1–100 символов) | `*` | `labmenu.exe lab6 "C:\Windows\*.exe"` |
| `lab7` | сколько процессов показать (1–50) | 10 | `labmenu.exe lab7 20` |
| `lab8` | задержка между чтением и записью, мс (0–10000) | 3000 | `labmenu.exe lab8 5000` |

## Коды возврата

Общие для всех лабораторных: `0` — норма, `2` — неверный аргумент, `3` — ошибка файла или WinAPI. Код `1` у каждой лабораторной свой:

| Команда | Значение кода `1` |
|---------|-------------------|
| `lab2` | в папке нет ни одного файла |
| `lab3` | свободной памяти меньше заданного минимума |
| `lab4` | найдено меньше букв, чем запрошено |
| `lab5` | файлов меньше, чем N (или файлов нет) |
| `lab6` | подходящих файлов нет |
| `lab7` | есть процесс с более чем 100 потоками |
| `lab8` | блокировку пришлось ждать дольше 100 мс |

Код `3` у `lab4` означает, что `GetLogicalDrives` вернула 0. Для `lab2` в режиме командной строки код можно проверить так: `echo %ERRORLEVEL%`.

## Создаваемые файлы

Лабораторные пишут файлы в **текущую папку**:

- `processes.csv` и `top.txt` — `lab7`;
- `counter.bin` — `lab8` (4 байта, значение счётчика).

## Проверка lab8 (блокировка файла)

Откройте два окна консоли в одной папке и запустите почти одновременно:

```
labmenu.exe lab8 5000
```

Первая копия прочитает `0`, подождёт и запишет `1`. Вторая будет ждать снятия блокировки, прочитает `1` и запишет `2`. Без блокировки обе записали бы `1`, и один запуск потерялся бы.

## Структура проекта

```
labmenu/
├── main.c            меню и разбор командной строки
├── labs.h            объявления lab2_run … lab8_run
├── lab2.c … lab8.c   лабораторные работы
├── labmenu.vcxproj   проект Visual Studio
└── labmenu.slnx      решение Visual Studio
```

Каждая лабораторная — функция `labN_run(int argc, char *argv[])` с сигнатурой `main`: `argv[0]` — имя лабораторной, дальше параметры.

## Известные ограничения

- `lab2` не обходит подпапки (упрощение сделано намеренно).
- `lab5` учитывает не более 256 файлов папки; лишние пропускаются с предупреждением. Если на границе топ-N несколько файлов одинакового размера, строк в списке будет больше N.
- `lab7` обрабатывает не более 512 процессов.
- Пути длиннее `MAX_PATH` (260 символов) не поддерживаются.
